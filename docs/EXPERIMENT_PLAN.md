# 从假设到证据

## H1：提交前复核可能改善答案，但会消耗预算

实现：baseline 原始循环；verify 在首个候选之后要求新的成功 Python 执行。
只给公开问题/执行历史，不传 reference_answer，不依据 evaluator 结果触发反思。
默认两策略总预算各 6 次请求，token、工具、延迟都记录。

实验顺序：

1. 离线故障注入验证协议与日志，不验证模型能力。
2. Docker 集成边界验收；本机已通过 7 项真实容器测试，不是完整安全审计。
3. `probe` 用一条短文本检查认证/端点；随后真实单题检查工具调用协议。
4. 在 dev 上两策略各 12 题 × 3 repeats，分析每个失败类别和成本。
5. 冻结代码和提示词后，在 holdout 上各 12 题 × 3 repeats。
6. 对比配对恢复/退化、正确率、请求/调用、完整 token 和延迟。

当前 both 命令按固定 schedule_seed 打乱题目，每个 task/repeat 相邻执行两策略，
交替先后顺序，并写入 manifest。每题独立上下文，无跨题记忆。此设计减少
顺序偏差；供应商变化仍可能混淆结果。温度 0 不保证复现。
2026-10-06 已通过真实 API 与单题配对验收；不填写预期提升百分比。

## 预先冻结的最小真实实验

采用 `--policy both --max-steps 6 --schedule-seed 0 --repeats 3 --max-api-calls 432`。
dev 12 题 × 3 次 × 2 策略，最多 432 次 API 请求，不是实际花费。
单题协议通过后才扩大；每次尝试记录实际 usage、错误、延迟，缺失用 unknown。
先分析 dev，若改动提示词/逻辑，必须重新跑同版本基线；随后冻结版本和题目。
holdout 使用同预算但不同生成种子，最多另外 432 次请求。不能边看 holdout
成绩边修改，然后仍把它叫未见测试。保存负结果、退化配对和未完成项。

运行前用 `--dry-run` 检查计划。报告恢复/退化数、分题型正确率和额外成本；
只凭 3 次重复不做显著性声明。两个入口分别运行时，报告标注 separate batches，
不要把它当作同批交替实验。自由 ask 会话和 API probe 不计入正确率。

旧 probe 的 AuthenticationError 记录保留。更新凭据后，真实 probe 已返回 OK；
单题配对已通过。开发筛查发现 WSL 连接超时、数字字符串以及复核附加解释的
格式失败，两个中断批次单独保留，不作为完整 benchmark。仅延长连接保留期、
澄清公开 JSON 类型和复核提交契约；不修改题目、标准答案、评分器或请求上限。
改动已通过离线测试和真实加权均价回归，之后冻结代码进行完整 dev / holdout。
请求次数上限不等于人民币上限，未取得完整 usage 时不填写虚构费用。
认证、权限、模型端点错误会中止整批；保存失败和未运行分母，不重复消耗请求。
普通 Ctrl+C 会把批次标记为 aborted，保留部分轨迹；强制杀进程不保证执行 finally，
需检查该批次所属容器。本次两次强制中断留下的已退出容器已按确切挂载归属清理。

## 解释限制与下一步

这是 4 类合成数据分析任务；holdout 只是不同生成种子。不能证明跨数据集、
编码环境或真实业务泛化；三个 repeat 也不自动获得统计显著性。
成功执行 Python 不保证独立算法，不是外部 verifier。复核可能固化原始错误。

若真实结果没有提升或成本显著增长，先报告负结果、分类失败，再提出 H2。
不要为了好看添加未评测的 memory、规划、多 Agent、SFT/RL。
若要扩大环境类型，应先加入可独立验证的编码任务及对应执行隔离/评分器。
