# 研究定位：先评估测试时复核，再讨论学习

本项目不把方法名称当作效果证明。当前研究问题是：在相同请求上限内，提交前
增加一次工具支持的复核，是否改善确定性任务的正确率，以及增加多少计算成本。
两策略独立上下文、共享公开任务，参考答案只在交卷后由本地 evaluator 使用。

## 为什么值得测，而不是预设一定有效

- [Self-Refine](https://arxiv.org/abs/2303.17651) 研究使用同一个模型反复反馈、修订，
  不需要训练或 RL。它提供测试时改进的思路，不意味着本项目 CSV 任务必然受益。
- [Large Language Models Cannot Self-Correct Reasoning Yet](https://arxiv.org/abs/2310.01798)
  对缺少外部反馈的推理自我修正提出限制。本项目让复核得到新的工具执行证据，
  但执行成功仍不等于计算逻辑正确，因此需要统计恢复、退化和额外用量。
- [Reflexion](https://arxiv.org/abs/2303.11366) 通过语言反馈和 episodic memory 影响
  后续尝试，并非更新模型权重。本项目当前没有跨任务记忆，不能称为复现 Reflexion
  或已经完成强化学习。

以上是方法基础，不是截至 2026 年的全面前沿综述；也不借用论文里的提升数字。
Pi 的工程借鉴另见 [PI_REFERENCE.md](PI_REFERENCE.md)，未移植其源码或依赖。

## 本轮可解释的控制

1. baseline 与 verify 共用模型、数据、类型说明、执行后端和最多 6 次请求。
2. 验证消耗同一请求上限；实际请求、tool、token、耗时仍分别统计，不宣称等费用。
3. 三次重复降低单次偶然性的影响，但同题重复不是独立新任务，不直接宣称显著性。
4. dev 允许发现问题、改进；holdout 在冻结后运行，不能看着测试分数调参。
5. 网络中断、格式失败和计算错误分开记录；中断批次不包装成完整 benchmark。
6. 模拟故障注入只展示工程恢复流程，不能混进真实模型结果。

## 后续选择由证据决定

- 若复核在可靠完整运行中只增加成本：不默认开启，不为了名字加入 memory。
- 若有计算/筛选失败：先提出具体复核假设，并加入相应计算预算对照。
- 若题目全部很容易：承认天花板效应，下一轮建立独立可验证的挑战开发集。
- 只有得到足够多、独立验证、去污染的轨迹后，再评估小模型 SFT 的可行性。
- RL/RLVR 需要训练模型、算力、奖励可靠性与独立评测，是后续研究阶段而非本轮交付。
